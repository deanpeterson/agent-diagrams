GitOps + operator: desired state in Git becomes running reality

ArgoCD keeps the cluster's CRs matching Git · the operator keeps reality matching the CRs — two continuous reconcile loops

desired state — the agent's gitops repo ArgoCD sync — Git → CR instances (every 60s) CR instances — validated against the CRDs operator reconcile — CRs → reality + status

Two reconcile loops. An ArgoCD ApplicationSet discovers each …-agent-gitops repo and an Application keeps the cluster's CRs matching Git. The operator watches AgentGateway / AgentWorkstation / KnowledgeBase instances (validated against their CRDs) and keeps reality — the gateway pod, the KB volume, the Mattermost presence — matching the CRs, writing status back. Declarative, self-healing, reversible: delete the repo and it all unwinds, no orphans.
